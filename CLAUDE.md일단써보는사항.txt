## 반드시 지킬 것
### 파일 경계 - 가장 중요
- 각 작업자는 'Assets/_Game/<본인이름>/**' 안에서만 쓰기가 가능하다. 그 밖의 모든 경로는 읽기 전용. 절대 폴더 밖 수정, 생성, 삭제 금지. 필요할 경우 꼭 팀장에게 물어본다. 사용자 폴더에 대한 추측 절대 금지이고, 확신하지 않는다면 꼭 사용자에게 확인받는다. 공용 코드의 경우 Assets/_Game/Hub 와 같은 곳이다. 사람 이름의 폴더는 공용이 절대 아니다.
- 첫 작업 시작 시 Claude의 Todo : 이번 작업 담당자 이름과 쓰기 가능 경로를 확인한 후 사용자에게 꼭 승인하도록 확인받는다.
- 에셋 임포트·이동은 반드시 에디터에서. 스프라이트/모델/오디오 임포트, 파일 이동·이름 변경·삭제는 **Unity 에디터 안에서** 한다. 탐색기 조작은 `.meta` 파손 → 머지 충돌.
- Claude는 `.cs`와 텍스트 데이터까지만 다루고, **에셋 이동/삭제는 "에디터에서 직접 해주세요"로 사용자에게 넘긴다.**
- 절대로 main 브랜치에서 작업하면 안된다. 각자의 이름으로 판 브랜치에서만 작업하고, 작업이 끝났다면 Pull Request를 올려 충돌을 확인한 후에 메인에 머지한다. 머지는 팀장인 제가 확인 후 할 예정이니, 임의로 머지하면 안된다.
- 작업 시작 전에 항상 깃허브 데스크탑에서 본인 브랜치가 맞는지 확인하고, 상단 메뉴바 Branch -> Update From Main으로 메인 작업을 풀 받으신 뒤 작업을 시작한다.
- 커밋하면 안되는 친구들은 .gitignore에 명시되어있어 자동으로 제외되니 변경한 모든 사항을 커밋해주시면 된다.


## 작업 방식
- 기능 구현을 요청받으면, 바로 코드를 쓰지 않고, 만들거나 고칠 파일과 방법을 계획으로 보여준 뒤 사용자 승인 이후 실제로 작성한다.
- 개념 설명 시 일반적인 예시보다 실제 스크립트를 예시로 든다.
- 추측하지 않는다. 기획이 빈 부분은 임의로 확정짓지 말고 질문한다.
- 주석은 한국어로 작성하고 의도(why)만. 코드를 번역한 주석은 금지.
- 결과 보고 형식 : 변경/생성 파일 목록, 핵심 변경 요약, 에디터에서 사용자가 직접 해야 하는 작업 목록, 남은 TODO (매 작업 종료 시)

## 커밋 컨벤션
커밋 컨벤션은 접두어를 통해 정한다. 이후 작업 내용을 요약한다.
- [Feat] : 기능 추가
- [Fix] : 버그나 내용 수정
- [Refactor] : 동작은 그대로, 코드 리팩토링
- [Asset] : 에셋 및 패키지 추가, 교체

## 코드 이름 규칙
- 클래스 : PascalCase ) PlayerMovement
- 메소드 : PascalCase ) SkipLevel()
- 필드 : camelCase ) itemCount
- 상수 : 대문자 ) MAX_STEP

## 공통 파일 규칙
모든 씬에서 공유하는 공통 파일 경로는 'Assets/_Game/Hub 폴더 내에서 이뤄진다.
- 사운드 : (오디오 매니저는 하나로, 사운드 데이터는 SO로 관리, 사운드 믹서 등의 내용)
- 옵션 UI : (옵션 전용 캔버스를 프리펩화하여 각 씬에 배치하는 등의 내용)
